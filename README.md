# 티니핑 도감 (Teenieping Compendium)

브라우저에서 **파일을 직접 열어도** 동작하는 정적 팬 도감 사이트입니다. 별도 빌드/서버가 필요 없습니다.
시즌1~6 및 극장판 **전체 157마리**를 수록합니다.

## 실행
`index.html` 를 브라우저로 열면 됩니다. (더블클릭)

## 페이지
- **`index.html`** — 전체 목록. 이름 검색 + 기수/등급 필터 (상태가 URL 에 남아 뒤로가기해도 유지됨).
  성별은 필터가 아니라 카드의 태그로만 보여 줍니다.
- **`p/<id>.html`** — 개별 티니핑. 대표 이미지·이름·태그(기수·등급·성별·감정)·마법·에피소드,
  그리고 1차 관계 목록. ⚠️ 자동 생성 — 빌드 때 내용까지 다 그려 넣는 **정적 페이지**입니다.
- **`quiz.html`** — 이름 맞추기. 난도 3종(🍭 쉬움: 3지선다 / 🍨 보통: 이름 가리기 / 😎 어려움: 실루엣).
- 상단 바의 **🔮 랜덤핑** — 아무 티니핑이나 무작위로 보여 줍니다.
- 상단 바 오른쪽 끝의 **공유 버튼** — 공유 시트(모바일)를 띄우거나 링크를 복사합니다.

## 데이터 구조 (중요)

`data/teeniepings.js` 는 **자동 생성 파일이라 직접 수정하면 안 됩니다.**
아래 원본들을 고친 뒤 다시 빌드하세요.

```
tools/roster.js      ← 전체 명단 + 등급 (PDF 공식 도감 + 극장판)   [권위 있는 명단]
tools/details.js     ← 특징·관계·영문명 (위키 리서치 상세)
tools/magic.js       ← 마법 설명 (개별 페이지의 '🪄 마법' 칸)
tools/ep-*.json      ← 에피소드 줄거리·회차 (기수별 파일)
tools/gender.json    ← 성별 (나무위키 정보상자에서 수집)
        ↓  node tools/build-data.mjs
data/teeniepings.js
```

### 다시 빌드
```bash
node tools/build-data.mjs     # 데이터
python3 tools/build-og.py     # 미리보기 카드 이미지 (images/og/)
node tools/build-pages.mjs    # 개별 페이지 157개 (p/<id>.html)
```

> 개별 페이지는 **정적 파일이라 빌드해야 반영됩니다.** 이름·마법 설명·관계·이미지를 고쳤다면
> 세 개를 순서대로 돌리세요. `data/teeniepings.js` 만 고치고 빌드를 잊으면
> 목록·퀴즈는 바뀌는데 개별 페이지만 예전 내용으로 남습니다.

빌드가 하는 일:
- 로스터의 각 이름에 **id 자동 생성**(한글→로마자 변환) — 기존 id/이미지는 `ID_OVERRIDE` 로 고정 유지
- 상세를 `(기수, 이름)` 으로 매칭해 병합 (실패 시 접두어 제거 후 이름 단독 매칭)
- 관계(relations) id 를 최종 id 로 **재매핑**하고, 세트 밖 참조는 제거
- 관계 **양방향 보정** (A→B 가 있으면 B→A 도 추가)
- 마법 설명은 `magic.js` 에서 **이름(nameKo)** 으로 병합 (`magic` 필드)
- 상세가 없는 캐릭터는 마법/에피소드를 비워 두고, 색상은 시즌 색을 변주해 자동 배정
- 이미지 내용의 짧은 해시를 `imgv` 로 기록 → `imageMarkup` 이 `?v=<해시>` 를 붙인다

> **왜 `imgv` 가 필요한가**: GitHub Pages 는 `max-age=600` 으로 응답합니다.
> 목록 페이지는 방문할 때마다 썸네일 157장을 받으므로 브라우저에 전부 캐시됩니다.
> 그림을 고쳐 배포해도 파일 이름이 같으면 캐시된 옛 그림이 계속 보입니다.
> 반면 개별 페이지 이미지는 그 캐릭터를 열어야 받으므로 캐시가 없어 바로 바뀝니다 —
> **같은 배포인데 개별 페이지만 바뀌고 목록은 안 바뀌는 것처럼 보이는 이유**입니다.
> 그림이 바뀌면 해시가 바뀌어 URL 이 달라지므로 즉시 반영되고,
> 그림이 그대로면 해시도 그대로라 캐시가 유지됩니다.

### 상세 정보 추가하기
`tools/details.js` 의 `window.DETAILS` 배열에 추가하면 됩니다. 병합 키는 `nameKo` + `seasonKey`:

```js
{
  id: "kkareuping",          // 리서치용 임시 id (관계 참조에 사용)
  nameKo: "까르핑",
  seasonKey: "jewel",        // emotion | jewel | key | dessert | star | princess
  nameEn: "Tickleping",
  emotion: "짓궂음",
  traits: "특징 설명…",       // 사이트에는 표시되지 않는 리서치 메모
  story: "에피소드 줄거리…",
  relations: [ { id: "joaping", label: "단짝" } ],
  colorHex: "#7CB342"
}
```

### 마법 설명 추가하기
`tools/magic.js` 의 `window.MAGIC` 에 **이름 그대로** 넣으면 됩니다:

```js
window.MAGIC = {
  "까르핑": "마법 깃털 부채로 상대를 간질여 자지러지게 웃긴다. 정작 자신의 약점도 발바닥 간지럼이다.",
};
```

빈 문자열이면 개별 페이지에 "아직 정보가 준비되지 않았어요 🌱" 가 표시됩니다.

> 등급은 `details.js` 가 아니라 **`roster.js` 가 결정**합니다 (royal / legend / villain 배열).
> 등급 종류: **로열 · 레전드 · 일반 · 빌런**

## 이미지

`images/<id>.png` 가 있으면 그 이미지를, 없으면 `colorHex` 기반 **플레이스홀더 SVG** 를 자동 사용합니다.

### 일괄 수집
아래 순서로 실행하면 됩니다. (Node 18+, 외부 패키지 불필요)

```bash
node tools/fetch-images-og.mjs         # 나무위키 대표 이미지(og:image) 수집
python3 tools/balance-size.py --apply  # 배경 여백 정리 + 카드에서 크기가 고르게 보이도록 균형 조정
python3 tools/make-thumbs.py           # 원본 512px 상한 적용 + 썸네일(images/thumb/*.webp) 생성
```

`fetch-images-og.mjs` 는 문서의 `<meta property="og:image">` 를 읽습니다. 나무위키가 지정한
**대표 이미지**라 어떤 그림이 본인 것인지 추측할 필요가 없어 가장 정확합니다.
하츄핑 계열 6종은 문서가 하나로 합쳐져 있어 og:image 만으로는 폼을 구분할 수 없어 `SKIP` 으로 제외합니다.
다만 **구분할 방법은 있습니다.** 하츄핑 문서의 「시즌별 변신 폼」 절에는 폼마다 이미지가 따로 실려 있고
`img` 태그의 `alt` 에 폼 이름이 들어 있습니다 (`하츄핑시즌2-1`, `FLORA-HEARTSPING`, `베리하츄핑`,
`(티니핑5)스타하츄핑`, `프린세스 티니핑 하츄핑`). 이 `alt` 로 매칭하면 6종을 각각 받을 수 있습니다.

배경이 불투명한 이미지(흰 배경 등)는 `tools/cutout.py` 로 오려낸 뒤 위 두 단계를 돌립니다.

> 💡 **더 큰 원본을 찾으려면 문서 이미지를 전부 훑어야 합니다.** og:image 는 200px 안팎으로
> 잘려 있지만, 같은 문서 본문에 500~1000px 원본이 함께 실려 있는 경우가 많습니다.
> 문서의 `i.namu.wiki` 이미지를 모두 받아 **현재 이미지와 48px 축소 비교로 같은 그림인지 확인한 뒤**
> 가장 큰 것을 고르면 됩니다. 이 방법으로 34장을 평균 2.5배 키웠습니다.
>
> ⚠️ 나무위키 HTML 은 **파이썬 `urllib` 으로 받으면 본문이 비어 옵니다.** Node 의 `fetch` 를 쓰세요.

> ⚠️ **og:image 는 정확하지만 가장 크지는 않습니다.** 나무위키 og:image 는 200px 안팎으로
> 잘려 나오는 경우가 많아, 문서 본문에 실린 그림(500px 이상)보다 작을 수 있습니다.
> 일괄 교체할 때는 **기존 이미지보다 큰지 확인하고 덮어써야 합니다.**
> (실제로 이 확인을 빠뜨려 36장이 최대 6배까지 작아진 적이 있습니다.)

### 배경 오려내기 — `tools/cutout.py`
흰 배경 이미지는 모서리에서 flood fill 로 배경을 찾아 투명하게 만듭니다.
이때 **경계를 부드럽게 남기는 것이 중요합니다.** 그냥 알파 0 으로 지우면
알파가 0 아니면 255 인 이분법이 되어, 분홍 카드 배경 위에서 윤곽이 계단처럼 보입니다.
**허용 색차(`TOLERANCE`)를 낮게 잡아야 합니다.** 흰 배경 위의 흰 캐릭터
(고마핑의 흰 모자, 뽀송핑의 양털)는 배경과 색이 거의 같아서, 18~26 으로 두면
flood fill 이 캐릭터 안쪽까지 파고들어 **머리가 뭉텅 지워집니다.** 12 가 적당합니다.

`cutout()` 은 이진 마스크를 1px 침식한 뒤 흐려서 알파 경사를 만듭니다.
침식을 먼저 하는 이유는 경사가 흰 여백이 아니라 캐릭터 안쪽에서 시작하게 해
**흰 테두리(할로)가 남지 않도록** 하기 위해서입니다.

원본 PNG 부터 알파가 이분법인 경우도 있어(나무위키 이미지 일부),
그럴 때는 원본 알파도 함께 다듬습니다.

### 바다 티니핑 배경 — `tools/strip-heart-bg.py`
방울핑·찰랑핑·소라핑만 대표 이미지에 연하늘색 글로우가 깔려 있습니다.
색으로는 구분할 수 없습니다 — 배경 글로우와 머리카락 하이라이트가 둘 다 S≈0, V≈1 입니다.
대신 **경사**로 판단합니다. 글로우는 부드러운 그러데이션이라 이웃과 색차가 거의 없고,
캐릭터 윤곽에서는 색이 확 바뀝니다. 모서리에서 번져 나가되 이웃과의 색차가 3 을 넘으면
멈추게 하면 글로우만 지워집니다.

### 이미지 처리 시 주의 — 알파 채널
`canvas.paste(im, pos, im)` 처럼 **RGBA 이미지를 자기 자신을 마스크로** 붙이면
알파가 **제곱**됩니다(200→157, 128→64, 64→16). 파이프라인을 여러 번 돌리면
안티앨리어싱된 윤곽이 계단처럼 깨집니다. 투명 배경에는 마스크 없이 `paste`,
배경색이 있으면 `alpha_composite` 를 씁니다.

예전 방식(참고용으로 남겨 둠):

| 스크립트 | 방식 |
|---|---|
| `fetch-images.mjs` | Fandom 위키에서 문서 대표 이미지를 가져옵니다. 문서 제목이 **정확히 일치할 때만** 채택합니다. |
| `fetch-images-namu.mjs` | 나무위키 문서에는 시즌 전체 티니핑 틀이 실려 있고 `alt` 에 이름이 있습니다. 문서 몇 개로 수십 마리를 한 번에 수집합니다. |
| `fetch-images-namu-unique.mjs` | 마이너 캐릭터는 `alt` 가 `무제63 2024…` 라 이름으로 못 찾습니다. 대신 여러 문서를 모아 이미지 URL 등장 횟수를 세고, **그 문서에만 있는 이미지**(= 본인 프로필)를 고릅니다. |

> **오매칭 방지 원칙**: 세 스크립트 모두 확신이 없으면 채택하지 않습니다.
> 위키 검색은 유사어를 반환하고(`딩동핑` → `빛나핑`), 한 이미지에 두 캐릭터가 함께 담긴 경우도 있어
> **틀린 이미지를 넣느니 플레이스홀더를 두는 쪽**을 택했습니다.

못 받은 캐릭터는 `images/<id>.png` 로 직접 넣으면 자동 반영됩니다.

## 개별 페이지는 왜 정적인가

개별 티니핑 페이지는 빌드 때 내용까지 **다 그려서** `p/<id>.html` 로 저장합니다.
예전에는 `detail.html` 하나가 주소의 `?id=` 를 읽어 JS 로 그렸는데, 두 가지가 문제였습니다.

1. **한 마리를 보려고 157마리를 받았습니다.** `data/teeniepings.js` 는 199KB 인데
   그중 한 마리만 쓰고 버렸습니다. 지금은 페이지 하나가 6KB 남짓으로 자체 완결합니다.
2. **메신저 미리보기가 전부 똑같았습니다.** 카카오톡·슬랙의 크롤러는 자바스크립트를
   실행하지 않습니다. JS 로 그리는 페이지는 크롤러 눈에 빈 껍데기라, 어떤 티니핑을
   공유해도 같은 미리보기가 나왔습니다.

관계 그래프도 빌드 때 SVG 로 미리 그립니다. 157마리 중 118마리는 관계가 아예 없고
나머지도 최대 5개라, 브라우저에서 매번 배치를 계산할 이유가 없었습니다.

목록(`index.html`)과 퀴즈(`quiz.html`)는 그대로 동적입니다. 검색·필터·퀴즈는
전체 데이터가 필요해서 199KB 를 받는 게 맞습니다.

### 메신저 미리보기

```
p/<id>.html          페이지에 og 태그가 박혀 있음
images/og/<id>.jpg   미리보기 카드 1200x630 (목록 카드 모양)
```

> 폴더(`p/<id>/index.html`)가 아니라 파일 하나로 두는 이유: `file://` 로 열었을 때
> 폴더 주소를 누르면 사파리가 브라우저 대신 **파인더를 엽니다.**
> 웹 서버는 폴더 요청에 `index.html` 을 돌려주지만 `file://` 에는 그 규칙이 없습니다.

- 컷아웃 PNG 를 og:image 로 바로 쓰면 투명 배경이 검게 나오는 앱이 있어,
  배경을 깐 JPEG 카드를 `tools/build-og.py` 로 따로 만듭니다.
- `og:image` 는 **절대 주소**여야 합니다. 배포 주소가 바뀌면
  `tools/build-pages.mjs` 와 `tools/build-og.py` 위쪽의 `BASE` 를 고치세요.
- 카카오톡은 미리보기를 오래 캐시합니다. 잘못 올라간 뒤 고쳤다면
  [카카오 캐시 초기화](https://developers.kakao.com/tool/clear/og) 에서 주소를 넣어 지우세요.

### 목록 상태 유지

목록에서 검색·필터를 걸어 둔 채 한 마리를 누르면 그 상태가 `?from=` 에 실려 옵니다.
`js/page.js` 가 이걸 읽어 "← 목록으로" 와 관계 그래프 링크에 다시 붙여 주므로,
돌아갔을 때 보던 목록이 그대로 남습니다.

## 저작권 · 출처

### 만든 이유
2026년, **딸에게 보여주려고** 만들었습니다.
아이가 캐릭터 이름을 궁금해하고 "이건 누구야?" 하고 물어보는 일이 많아서,
한곳에서 찾아보고 이름 맞추기 놀이도 할 수 있게 정리한 것입니다.

공식 제작사와 아무 관련이 없는 **비공식 팬 페이지**이며,
**광고나 후원 등 어떤 형태의 수익화도 하지 않습니다.**

### 캐릭터 이미지
`images/` 의 캐릭터 이미지에 대한 모든 권리는 **SAMG엔터테인먼트**에 있습니다.
소개·감상 목적으로만 실었으며, **권리자의 요청이 있으면 즉시 삭제**합니다.

### 설명 · 에피소드 줄거리
마법 설명과 에피소드 줄거리는 **나무위키** 문서를 바탕으로 정리했습니다.
나무위키 문서는 **[CC BY-NC-SA 2.0 KR](https://creativecommons.org/licenses/by-nc-sa/2.0/kr/)** 라이선스를 따르므로,
이 프로젝트의 해당 텍스트도 **같은 라이선스**로 배포되며 **비영리 용도로만** 사용할 수 있습니다.

- 출처: <https://namu.wiki/w/티니핑> 및 각 캐릭터 문서
- 회차·방영일은 [위키백과 캐치! 티니핑 에피소드 목록](https://ko.wikipedia.org/wiki/캐치!_티니핑의_에피소드_목록)으로 교차 확인했습니다.

### 코드
`js/`, `css/`, `tools/` 의 코드는 자유롭게 쓰셔도 됩니다.

### 포크·재배포 시 유의
**광고나 후원 등 수익화를 붙이면 안 됩니다.** 나무위키 텍스트의 NC(비영리) 조건 위반이며,
이미지 저작권 측면의 위험도 크게 올라갑니다.
